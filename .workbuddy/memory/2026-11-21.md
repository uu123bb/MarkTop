# 2026-11-21

## MarkTop（C# WPF + WebView2 的本地 Markdown 编辑器）从零落地

工作区从空仓库开始，完成 M0–M4 主体：外壳、编辑器、预览、导出、Git README、单文件发布。

### 架构定稿
- `src/MarkTop.App`：WPF net10.0-windows，WebView2 单页单实例；`WebBridge` 走 `postMessage` + JSON。
- `src/MarkTop.Core`：配置/编码/换行/路径守卫/Git 客户端/HTML 导入，无 UI 依赖，22 个 xunit 用例。
- `src/MarkTop.Web`：TypeScript + esbuild，CodeMirror 6 源码区 + Vditor 4.0.1 预览/IR；markdownlint 走 Worker。
- 文本权威在 JS，C# 通过 `req.text` 请求-响应取全文，避免按键级跨进程推送。

### 踩过的坑（重要，别再犯）
1. **MSBuild 嵌入 web 资源**：`BeforeTargets="PrepareResources"` 内部再 `<ItemGroup><EmbeddedResource/></ItemGroup>` 不会生效，资源根本不会打进程序集。正解：在评估期静态声明 `EmbeddedResource`，并用 `BeforeTargets="PrepareForBuild"` 的 target 生成 zip。
2. `$(IntermediateOutputPath)` 在 `PrepareForBuild` 阶段还是空值，zip 会落到项目根目录。改用 `$(BaseIntermediateOutputPath)`。
3. **PowerShell 5.1 读 UTF-8 无 BOM 的中文 .ps1 会解析错乱**，脚本必须写 BOM。
4. 沙箱会拦截 `rm -rf dist`（>50 文件）。`build.mjs` 改为增量覆盖，不整目录删除。
5. Vditor 4.0.1 只有 UMD（无 ESM），`Vditor.preview` 在 KaTeX 资源加载完成前就返回，公式会保持原始 TeX → 需在 preview 后用 `katex.render` 补渲染。
6. `Vditor.md2html` 不跑 KaTeX/Mermaid/hljs。导出必须自己再走一遍：`katex.renderToString`、`mermaid.render` 转内联 SVG、`hljs.highlightElement`。
7. Chromium 不支持 `@page{size}`；PDF 尺寸/边距只能走 `ICoreWebView2PrintSettings`，且写了 `@page{margin}` 会覆盖 API 边距。
8. WebView2 非打包应用默认把 userDataFolder 建在 exe 旁，必须显式 `CreateAsync(null, %LOCALAPPDATA%\MarkTop\WebView2)`。
9. 单文件发布必须 `IncludeNativeLibrariesForSelfExtract=true`，否则 `WebView2Loader.dll` 加载失败。

### 术语约定（用户明确纠正）
- “所见即所得”是效果描述，不是功能/模式名。Vditor 的三种模式是：wysiwyg（所见即所得）、ir（即时渲染）、sv（分屏预览）。
- 本项目 UI、文档、注释一律用 **即时渲染** 指代 Vditor `mode: "ir"`，不要写成“所见即所得模式”。
